Issue Description (Required):

AWS max bandwidth errors (like BandwidthLimitExceeded) often stem from short network bursts (microbursts), instance limitations, or throttling, not just slow averages, with common causes being high packets per second (PPS) or throughput spikes hitting ENA limits, needing CloudWatch checks for metrics like bw_out_allowance_exceeded and solutions like upgrading instance types or implementing keepalives.
Common Causes & Solutions:
Microbursts & ENA Limits:
Problem: Your instance’s Elastic Network Adapter (ENA) has limits on bandwidth (Gbps) and PPS (Packets Per Second). Short, intense bursts (microbursts) can exceed these, triggering bw_out_allowance_exceeded or pps_allowance_exceeded in CloudWatch, even if your average usage looks fine.
Solution: Use CloudWatch to monitor NetworkIn, NetworkOut, bw_out_allowance_exceeded, and pps_allowance_exceeded for detailed insight. Consider an instance type with higher network performance or investigate if traffic shaping (like QOS) is needed.
BandwidthLimitExceeded (API Level):
Problem: A broader error indicating insufficient resources, sometimes related to network capacity.
Solution: Check for other errors like InsufficientInstanceCapacity or RequestLimitExceeded (if hitting API rate limits).
Throttling & Storage Gateway:
Problem: If using AWS Storage Gateway, you might have bandwidth throttling configured (upload/download limits).
Solution: Check your gateway settings to see if limits are intentionally set.
Connectivity & Security Groups:
Problem: Network issues outside the instance, such as restrictive Security Groups, Network ACLs, or routing problems, can also cause perceived bandwidth limits or timeouts.
Solution: Verify firewall rules and test connectivity from different locations.
Key Metrics to Check (CloudWatch):
NetworkIn/NetworkOut (Average throughput)
bw_in_allowance_exceeded/bw_out_allowance_exceeded (Bandwidth allowance exceeded)
pps_allowance_exceeded (Packet per second allowance exceeded)
conntrack_allowance_available (Connection tracking limits)
By checking these specific metrics and understanding microbursts, you can diagnose and resolve bandwidth-related errors in AWS.
