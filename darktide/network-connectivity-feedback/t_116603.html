Additional Technical Context (Network / Backend)

Based on repeated testing and log analysis, the connection issues (error codes 2001 / 2014 / 3013 / 4001) appear to be triggered by a combination of network-level packet deformation upstream and backend sensitivity to short-lived traffic bursts, rather than by client misconfiguration.

Observed Behavior

  • Client logs consistently show:

    • Resolving timed out

    • failed_handshake_timeout

    • pong_timeout

    • gRPC connection attempts to bsp-im-prod.atoma.cloud:443

  • Average latency and throughput appear normal, but connection failures occur during:

    • initial backend handshake

    • matchmaking / lobby join

    • keepalive ping-pong phases

  • The problem is more frequent in Russia but also reported in other regions, suggesting amplification rather than a strictly regional outage.

Key Observation

A combination of DPI-avoidance tooling (e.g. packet-level TLS fragmentation / ClientHello splitting) and traffic tunneling via Cloudflare WARP significantly reduces or fully eliminates the issue for many affected users.

This strongly suggests that:

  • The failures are not caused by slow average bandwidth

  • But by microbursts, packet reordering, or short packet loss events

  • Which are sufficient to disrupt gRPC / HTTP2 streams and backend keepalive logic

Likely Contributing Factors

  1. Upstream DPI / traffic inspection

    • Introduces packet fragmentation, delay, or reordering

    • Does not fully block traffic but deforms it

  2. gRPC over HTTP/2 sensitivity

    • High PPS patterns

    • Tight keepalive / ping-pong timing

    • Low tolerance to packet loss or reordering

  3. AWS ENA limits and burst behavior

    • Potential bw_out_allowance_exceeded or pps_allowance_exceeded

    • Silent packet drops during short traffic spikes

    • Effects amplified on long-haul routes with higher RTT variance

Why DPI Workarounds Appear to “Fix” the Issue

DPI-avoidance tools do not repair backend infrastructure; instead, they:

  • Prevent upstream packet deformation

  • Reduce retransmit amplification

  • Smooth traffic bursts before reaching AWS
    As a result, backend services receive traffic in a form they can handle reliably.

Suggested Areas for Investigation (Backend Side)

  • CloudWatch metrics:

    • bw_in_allowance_exceeded

    • bw_out_allowance_exceeded

    • pps_allowance_exceeded

    • conntrack_allowance_available

  • gRPC configuration review:

    • keepalive intervals and timeouts

    • tolerance for transient packet loss

    • retry / backoff behavior

  • Instance sizing and network performance class

  • Traffic shaping or buffering between matchmaking and mission instances

Summary

This appears to be a cross-layer interaction issue, where upstream network deformation exposes fragility in backend networking assumptions. Improving tolerance to packet reordering, microbursts, and transient loss would likely reduce or eliminate these connection failures without requiring client-side workarounds.
