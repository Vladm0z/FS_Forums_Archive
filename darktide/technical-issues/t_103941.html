It might be a stretch but I have a hunch for why this might be happening:

  • This thread timing lines up with when Microsoft was pushing out Windows 11 24H2 the update that breaks everything to more people
  • With 24H2 they rewrote part of the graphics display interface in Rust
  • GDI is old but is still part of WinAPI and the Windows DWM
  • Direct2D can interact with both GDI and Direct3D
  • some of OPs crashes mention Lua errors with Hud and view data

It’s worth mentioning that the part of GDI that was rewritten was Regions which can be used for getting the cursor location (sounds like UI and HUD to me).

Two other things stuck out when I got sucked down the wiki rabbit hole. From the Windows DWM page:

Writing the output of GDI to system memory is not hardware accelerated, nor is conversion to the DirectX surface. When a GDI window is minimized, invisible, or visible on the same monitor as a full-screen DirectX application, by limitation of GDI, the GDI bitmap buffer is no longer received by the application when requesting a device context during painting or updating (this can sometimes be seen when a GDI operation copying from one window to another output black or empty regions instead of the expected window content). Thus, DWM uses the last bitmap rendered to the buffer before the application was minimized.

Applications can mix either rendering techniques across multiple child windows, as long as both GDI and DirectX are not used to render the same window. In that case, the ordering between DirectX and GDI rendering cannot be guaranteed, and as such it cannot be guaranteed that the GDI bitmap from the system memory has been translated to the video memory surface. This means that the final composition may not contain the GDI-rendered elements. To prevent this, DWM is temporarily turned off, as long as an application that mixes GDI and DirectX in the same window is running.

From the Direct3D Page:

Direct3D implements two display modes:

  • Fullscreen mode: The Direct3D application generates all of the graphical output for a display device. In this mode Direct3D automatically captures Alt-Tab and sets/restores screen resolution and pixel format without the programmer intervention. This also provides plenty of problems for debugging due to the ‘Exclusive Cooperative Mode’.
  • Windowed mode: The result is shown inside the area of a window. Direct3D communicates with GDI to generate the graphical output in the display. Windowed mode can have the same level of performance as full-screen, depending on driver support.

I know the engine has been around for a while so it’s not impossible that it’s a GDI issue?

So either something breaks occasionally as a result of the Regions being updated, it interacts poorly with the DWM or doesn’t let the DWM doesn’t turn off when it should, or it’s a side effect of Darktide’s fullscreen option being borderless windowed (assuming it counts as Windowed for that last quote)
