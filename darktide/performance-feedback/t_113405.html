Summary of Performance Testing – Ryzen 9 5950X + RTX 3090

Hardware

  • CPU: AMD Ryzen 9 5950X

  • GPU: NVIDIA RTX 3090 (24 GB)

  • RAM: 64 GB

  • Storage: NVMe SSD (MP600)

  • OS: Windows 10, latest NVIDIA + AMD chipset drivers

Symptoms

  • Issue started after the April update and has persisted since then.

  • In Mortis Trials: game mostly sits around ~45–55 FPS, regardless of resolution (2560×1440, 1920×1080, down to 1024×768).

  • In regular missions: FPS frequently drops below 30 with heavy stutters and short “freeze” moments that feel like the game is about to crash.

  • Behavior is the same with different graphics presets and after multiple clean reinstalls + file verifications.

Measurements (MSI Afterburner logging)

From a long session with MSI logging enabled:

  • Average FPS: ~48 FPS (median ~48, 90th percentile ~61).

  • Frametime: median ~27 ms, with spikes up to 500+ ms (visible as hard stutters/freezes).

  • GPU usage: typically 30–40%, rarely above 80%, even when FPS drops below 30.

  • CPU usage: at least one core is 80–100% almost all the time (max per-sample core usage median ~83%).

  • Temps / memory:

    • CPU temps ~69–83 °C (no thermal throttling).

    • System RAM used ~19–33 GB of 64 GB.

    • VRAM used ~5.5–7 GB of 24 GB.

This strongly suggests a CPU/engine bottleneck with the GPU underutilised.

Game logs

  • console.log shows frequent stalls on [main] and [renderer] threads, such as:

    • Stall XXXX ms on frame … RI::wait_for_fence

    • ThreadPool::do_work_while_waiting_for_event

  • Some stalls are in the hundreds to >2000 ms, matching the visible freeze moments.

  • FrameRateManager reports 60 FPS cap in menus and uncapped (0) in missions, so there is no hidden 30 FPS cap.

Changes and tests performed

All of this has been tried, with no meaningful improvement in minimum FPS or stutter:

  • Worker threads

    • Default auto-detect set max_worker_threads = 29.

    • Overridden in user_settings.config and launcher to max_worker_threads = 8 (confirmed in launcher log).

  • Graphics settings (multiple combinations tested):

    • V-Sync off, frame cap 120 or uncapped.

    • Ray tracing fully off (dxr = false, RT reflections off, RTX GI off).

    • Ambient occlusion, baked DDGI, GTAO turned off or set to lowest.

    • Volumetric fog, global illumination, light quality on low.

    • Ragdolls, blood/impact decals, decal lifetime reduced to very low values.

    • Different resolutions from 1440p → 1080p → 1024×768 (FPS essentially unchanged, confirming it’s not GPU-bound).

  • System side

    • Clean reinstall of Darktide (multiple times) + file verification.

    • Latest NVIDIA GPU drivers.

    • AMD Chipset Software updated (7.06.x, reasonably current).

    • No overlays or heavy background processes during testing.

Conclusion / Ask

On this system (5950X + 3090), Darktide appears to be severely CPU/engine-bound, with:

  • Underutilised GPU (~30–40% usage at low FPS),

  • One or more CPU threads consistently near 100%, and

  • Frequent long stalls in the engine reported in console.log.

After extensive testing and configuration changes, there doesn’t seem to be anything left for me to optimize on my side that meaningfully improves performance. I would appreciate it if Fatshark could:

  • Confirm whether this matches any known CPU/engine issues/regressions, and

  • Advise if there are specific settings, launch options, or upcoming patches aimed at improving this kind of CPU-bound behavior on high-core-count CPUs like the 5950X.
