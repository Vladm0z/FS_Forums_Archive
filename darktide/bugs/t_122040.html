Issue Description (Required):

Darktide on Linux exits without actual crash (possible controlled shutdown / RPC issue)

System:

  • Linux Mint Cinnamon
  • NVIDIA RTX 4070 Ti
  • Driver 595.71.05
  • Kernel 6.8
  • X11 session
  • Steam Runtime enabled

Tested Proton versions:

  • Proton 9
  • Proton Experimental
  • Proton GE

Problem:
Darktide launches correctly and performs perfectly:

  • shaders compile normally
  • lobby loads correctly
  • missions load correctly
  • gameplay is smooth with no stutter, no freezes and no graphical corruption

However, after a short period in gameplay, the game suddenly exits directly to desktop.

Important:
This does NOT behave like a normal crash.
There is:

  • no freeze
  • no GPU reset
  • no Vulkan device lost
  • no black screen
  • no visible crash dialog

The game simply disappears instantly, almost as if a shutdown routine is triggered intentionally.

Findings:

  • earlycrashreports and crashdump folders remain empty

  • Proton logs repeatedly show:
    RPC_S_SERVER_UNAVAILABLE (0x6BA)

  • COM/RPC related modules appear repeatedly:

    • combase.dll
    • ole32.dll
    • actxprxy.dll
    • rpcrt4.dll
    • wininet.dll
    • urlmon.dll

Interesting observation:
A dump file contains the text:
“Detected shutdown”

The dump also contains references to:

  • telemetry
  • mission-event
  • CloudFront
  • http_cache.db

This makes me suspect:

  • a launcher/runtime/web/telemetry component fails
  • the game later performs a controlled shutdown instead of a real crash

Additional notes:

  • Other Steam games run perfectly on this system
  • GPU and Vulkan initialization complete successfully
  • Darktide itself renders and performs flawlessly until exit

It may possibly be a recent Proton/Darktide regression related to RPC/COM/web runtime interaction.
